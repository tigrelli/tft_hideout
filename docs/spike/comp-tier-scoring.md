# DATA-23 스파이크 — 자체 티어 스코어링 재설계 (2026-08-18)

DATA-23(자체 티어 스코어링에 표본 신뢰도 반영 검토) 착수 전, PM과의 세션에서 후보 알고리즘 여러 개를 실측 데이터로 미리 검증했다. DATA-23을 실제로 구현할 때는 이 문서를 그대로 설계 근거로 삼고, 필요시 재검증만 하면 된다(전체 재조사 불필요).

## 배경

DATA-21(완료, 2026-08-16)의 `assign_self_tiers()`는 avg_place·win_rate 두 축의 순위(Borda count)만으로 OP/S/A/B/C를 매기는데, 실측 결과 표본 크기(`compsCount`)·픽률(`pickRate`)을 전혀 반영하지 않아 **가장 적게 플레이된(pickRate 0.099%, 최소표본 1,318회) 조합이 자체 계산으로 "OP"를, 가장 널리 플레이된(pickRate 1.471%, 최대표본, op.gg 원본도 "OP") 조합이 "B"로 강등되는 역전**이 확인됨(DATA-23 등록 사유, 진행현황.md 2026-08-18 참고).

## 스키마 정정 (중요)

`totalCount`는 개별 조합의 표본 게임수가 **아니라** 이번 집계구간 전체 게임수(모든 조합 공통 분모, 현재 10개 조합 전부 동일값)다. **개별 조합의 실제 표본 게임수는 `compsCount`**다(`pickRate=compsCount/totalCount`, `winRate=winCount/compsCount` 수식으로 검증 완료). 상세: `docs/spike/opgg-schema.md` 10번 항목.

## 검토한 후보 4개 (오늘자 실제 10개 조합 데이터로 계산)

| 후보 | 방식 | op.gg 원본과 일치(10개 중) |
|---|---|---|
| 현재 DATA-21(2축, 순위기반) | avg_place+win_rate 순위 합, 고정 퍼센타일 5단계 | 1개 |
| 옵션A(pickRate 3축 추가, 순위기반) | 위+pickRate 순위, 고정 퍼센타일 | 3개 |
| ChatGPT 추천(4지표 값기반+opScore 50% 앵커) | place40%+top4 35%+win15%+pick10%(sqrt완화) 을 opScore 50%와 블렌드, 고정 퍼센타일 | 4개(단, 상위 2개 클러스터는 정확히 일치) |
| ChatGPT 지표만(opScore 미사용, 4지표 값기반) | 위와 동일 가중치, opScore 제외 | 니치 조합(이즈리얼) 1위 재현 — 실패 |
| **opScore 100% + 상대임계값 간격 클러스터링** | 아래 "최종 확정 알고리즘" 참고 | **10개 전부 일치** |

핵심 상관관계 분석: `opScore`는 `avg_place`(r=-0.225)·`win_rate`(r=-0.243)·`top4_rate`(r=-0.232)와는 거의 무관하고, **`pick_rate`와는 r=+0.984(거의 완벽한 상관, R²≈0.97)**. 즉 op.gg의 opScore는 이 top-10(이미 성능으로 1차 필터링된 집합) 안에서는 사실상 **픽률(대중성·신뢰도)의 대리 지표**다.

## 정의 재확정 (PM 확인, 2026-08-18)

DATA-21 원래 목표("객관적 최강 조합 판별")는 이 데이터 소스로는 근본적으로 달성 불가능하다(모집단이 이미 top-10으로 필터링됨, 관찰 데이터라 선택편향/역인과 분리 불가, "강함"이 다차원 개념이라 스칼라 압축 자체가 손실을 수반). 따라서 목표를 다음으로 재정의한다:

> **"op.gg가 제공하는 top 10 조합 중, op.gg 자체 종합점수(opScore)가 반영하는 대중성·신뢰도를 기준으로, 이 10개 안에서 자연스러운 점수 격차를 찾아 우리가 직접 재구간화한 상대적 티어"**

opScore를 신뢰하기로 한 것이지 op.gg의 **이산 라벨(OP/S/A 등)**을 그대로 신뢰하는 게 아니다 — 그 라벨은 op.gg의 훨씬 큰 모집단(20개 이상, 랭크 필터 가능) 기준 절대 임계값이라 우리의 10개 한정 모집단에 그대로 적용하면 DATA-21이 처음에 발견한 문제(모집단 불일치로 배지가 어긋남)가 재발한다. 그래서 **연속값(opScore)만 가져오고, 구간화(어디까지가 OP인지)는 우리가 우리 모집단(10개) 안에서 직접 계산**한다 — 이 부분이 DATA-21의 "op.gg 배지 그대로 저장하지 않는다"는 원칙과 여전히 일치한다.

## 최종 확정 알고리즘

```
1. opScore를 0~100으로 Min-Max 정규화 (같은 배치 10개 조합 내에서)
2. 정규화 점수 내림차순 정렬
3. 인접 순위 간 점수 격차(gap) 계산
4. 평균 격차 × 1.3 을 넘는 지점만 "진짜 경계"로 인정
   (고정 5단계 강제 배분 안 함 — 그날 점수 분포에 따라 3~5단계로 가변적,
    최대 5단계(OP/S/A/B/C)까지만 허용)
5. OP부터 순서대로 라벨 부여
```

**검증 결과**: 2026-08-18 실제 10개 조합 데이터에서 op.gg 원본 opTier 라벨과 **10/10 완벽 일치**(place/top4/win 성능축을 섞을수록(30%~70% 블렌드) 오히려 일치도가 4~5/10으로 떨어짐 — opScore 단독이 최선이었음, 위 표 참고).

## ⚠️ 반드시 확인 후 구현할 것 — 과적합 위험

**임계값 `1.3`은 2026-08-18 하루치 10개 데이터(n=10)에 맞춰 탐색적으로 찾은 값**이라 이 특정 스냅샷에 과적합됐을 위험이 있다. DATA-23 착수 시:

1. 며칠(가능하면 여러 패치에 걸쳐) 배치 실행 결과를 모아 같은 임계값(1.3)이 안정적으로 op.gg 원본과 잘 맞는지 재검증할 것.
2. 필요하면 임계값을 다시 튜닝하거나, 매번 다른 임계값이 필요한 것으로 나오면(불안정하면) 더 견고한 방법(예: 표준편차 기반 이상치 탐지, 계층적 클러스터링의 실루엣 점수로 자동 k 결정)으로 대체 검토.
3. 단일 배치(10개)만으로 검증하지 말고 최소 3~5개 이상 서로 다른 시점의 스냅샷으로 교차검증(재현성 확인) 후 PM 승인받을 것.

## DATA-22/DATA-23 범위 조정

opScore가 이미 top4Rate·pickRate 정보를 사실상 담고 있어(위 상관관계 분석), **티어 "계산" 자체에는 더 이상 top4Rate/pickRate/traits가 필요 없다.** DATA-22가 가져오는 이 필드들은 DATA-23의 계산 로직과는 무관하며, 조합 상세 페이지 등에 "표시"용 부가 정보(API-16/FE-18 목적)로만 사용한다. DATA-23은 `comps.op_score`(신규 컬럼 필요, 현재 저장 안 됨) 하나만 있으면 계산 가능 — 이 컬럼 추가가 DATA-23 스코프에 포함되어야 함(DATA-22와 무관하게 독립적으로 착수 가능하도록 선행TASK 재검토 필요).

## 한계에 대한 인식 (알고리즘과 별개로 중요)

"어느 덱이 실제로 강한가"는 이 데이터 소스만으로는 원천적으로 답할 수 없는 질문이다(선택편향, 모집단이 이미 top-10으로 필터링됨, 랭크·상대방 등 맥락 정보 부재, "강함"의 다차원성, op.gg opScore 자체도 블랙박스). 따라서 이 알고리즘의 목표는 "객관적 진실"이 아니라 "우리가 가진 제한된 데이터 안에서 내적으로 일관되고 설명 가능한 상대 순위"이며, FE-16(티어 배지 데이터 출처 안내 문구)의 사용자 고지와 함께 이 한계를 계속 투명하게 전달하는 것이 알고리즘을 더 정교하게 만드는 것보다 우선한다.
