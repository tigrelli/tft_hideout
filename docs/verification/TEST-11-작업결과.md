- **[관찰, 하네스 한계]** H5, H11 — 위 "주의" 참고, 실제 멀티턴 세션 없이는 정확히 검증 불가(현재 단일턴 응답 자체는 각각 "확인되지 않았습니다"/정형 오프토픽 거절로, 명백히 틀렸다기보다 맥락 부재 상태에서의 안전한 회피에 가까움).

## Groq 할당량 운영 교훈 (중요 — 다음 세션 페이싱에 필수)

원본 Render 로그(PM 제공): `docs/verification/TEST-11-render-log-groq-tpd-exhausted-2026-08-14.txt` — `GROQ_STREAM_ERROR ... RateLimitError ... tokens per day (TPD): Limit 100000, Used 99798` 확인.

- Groq 무료 티어는 `llama-3.3-70b-versatile` 모델 기준 **TPD(토큰/일) 100,000**. 카테고리 A 25문항 하나만으로 거의 소진됨(질문 1개당 오프토픽 2차 판별·의도분류 2차 판별·본답변 생성·후속질문 생성까지 최대 4회 Groq 호출).
- **[2026-08-16 갱신] Groq가 `llama-3.3-70b-versatile`을 폐기하고 `openai/gpt-oss-120b`로 전환됨(CHAT-23)** — 새 모델의 무료 티어 TPD는 **200,000(2배)**이지만 TPM은 8,000으로 기존(12,000)보다 낮음. 하루 총량 제약은 완화됐으나 "롤링 윈도우" 특성 자체는 Groq 공통 정책이라 카테고리 하나(20문항 안팎) 처리 후 쉬어가는 페이싱 원칙은 새 모델에서도 유지할 것 — 다만 정확히 몇 문항까지 여유가 있는지는 새 모델 기준으로 아직 실측되지 않았으니 다음 세션에서 보수적으로 접근할 것.
- **자정에 리셋되는 고정 일일 한도가 아니라 24시간 롤링 윈도우로 추정된다**(2026-08-14 세션에서 실측 확인 — 카테고리 A 직후 "안녕" 같은 아주 가벼운 호출은 통과했지만, 곧이어 카테고리 B 10문항은 전부 실패). 즉 큰 배치를 소화한 직후엔 몇 시간이 지나도 여유가 크게 안 생길 수 있다.

- **[2026-08-16 추가 확인] 롤링 윈도우는 세션이 아니라 달력상 하루 단위로 여러 세션에 걸쳐 공유된다.** 같은 날 앞선 세션에서 C(20)+D(15)=35문항을 이미 소화한 뒤, 새 세션에서 가벼운 호출 + 소량(3문항) 프로브까지는 통과했으나 곧이어 E 15문항 본 실행 4번째 문항(E3)부터 다시 폴백 시작(11/15 무효). 즉 **프로브 통과 ≠ 본 실행 끝까지 안전** — 그날 이미 다른 세션에서 카테고리를 하나 이상 처리했다면 그날은 추가 진행을 피하고, 본 실행 중 다시 폴백이 나오면 그 시점에서 즉시 중단해 남은 문항을 다음 기회로 미룰 것.
