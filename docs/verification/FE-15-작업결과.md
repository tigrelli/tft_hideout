- **상태**: 완료(PM 승인)

## 배경

FE-14(실좌표 헥스 배치도) 완료 다음날, PM이 op.gg 원본 화면 스크린샷(챔피언 아이콘 위에 초록/파랑/핑크/회색 등 색깔 별이 표시됨)을 첨부하며 최종 챔피언이 2성인지 3성인지 별 표시를 추가할 수 있는지 문의. op.gg `tft_list_meta_decks` 응답을 재조회한 결과 `units[].tier`(정수, 관측값 2·3)에 성급 데이터가 있음을 확인 — FE-14의 `cell.{x,y}`와 같은 unit 객체 필드였지만 그동안 추출하지 않고 있었음(`docs/spike/opgg-schema.md` 8번 항목 참고).

op.gg 원본의 별 색상 체계(초록/파랑/핑크/회색 등)는 무엇을 기준으로 나뉘는지 확인할 근거 데이터가 없어(우리가 가진 값은 `tier` 정수 하나뿐) 그대로 재현하지 않기로 하고, PM이 **3성=레드/2성=골드 2단계 고정 색상**을 직접 결정. 기존 티어 배지 색상 토큰(design-tokens.md, `--color-tier-op: #d9463d`(레드) / `--color-tier-s: #e5b93d`(골드))을 그대로 재사용해 새 색상값을 만들지 않았다.

## 로컬 브라우저 실검증 (2026-08-06, PM 요청으로 추가 진행)

PM이 "로컬에서 확인할 수 있나요?"라고 요청해, 이미 로컬에서 돌고 있던 개발 백엔드(uvicorn `--reload`, 포트 8000, 개발 Supabase DB 연결)·프론트엔드(포트 3000) 프로세스를 그대로 활용해 실제로 확인했다.

- **경위**: 코드 수정이 `--reload`로 기존 로컬 백엔드에 즉시 반영되면서, 개발 Supabase DB에는 아직 `star_level` 컬럼이 없어 `GET /comps/{id}`가 500을 반환하기 시작함을 발견 — 즉시 마이그레이션(`d4f0e13a125e`)을 개발 DB에 적용해 복구.
- **운영(개발) 데이터 백필 완료**: FE-14와 동일 패턴으로 op.gg `tft_list_meta_decks`를 1회 재호출해 `comp_champions.star_level`만 UPDATE하는 1회성 스크립트를 개발 Supabase DB에 직접 실행(레포 미커밋, 다른 테이블 미변경) — 10개 조합 중 8개(69명, FE-14 백필과 정확히 동일한 매칭 결과) 반영.
- **실제 화면에서 크리티컬 버그 발견·수정**: Playwright로 실제 배포와 동일한 조합("N.O.V.A. 아칼리", 사용자가 처음 문의했던 그 조합)의 상세 페이지를 캡처한 결과, 8명 중 6명(잭스·아칼리·마오카이·우르곳·모르가나·아트록스)의 별이 화면에 전혀 안 보이고 2명(킨드레드·케이틀린)만 보임. `getComputedStyle`로 확인하니 6명 모두 `color`/`opacity`/`display`가 전부 정상이라 DOM·CSS 로직 자체는 문제없었음 — **크로미움이 clip-path 형제 요소(HexIcon의 육각형 클리핑)와 같은 스태킹 컨텍스트를 공유하는 인라인 텍스트를 실제로 페인트하지 않는 렌더링 버그**로 원인을 좁힘(별이 보였던 2명은 우연히 벌집 오프셋 때문에 이미 `transform`이 걸려 있어 별도 컴포지팅 레이어가 생겼던 것). `StarRating`에 `transform-gpu`(자체 컴포지팅 레이어 강제)를 추가해 8명 전원 정상 렌더링 확인.
- **최종 스크린샷 확인**: 잭스·아칼리 3성(레드 ★★★), 마오카이·우르곳·모르가나·아트록스·킨드레드·케이틀린 2성(골드 ★★) 전부 정상 표시, 배치 순서도 PM이 첨부한 참고 화면(op.gg)과 동일(잭스 위 → 중앙 5명 → 킨드레드/케이틀린 아래)함을 확인.
- 검증 후 로컬 임시 프로세스(seed/backfill 스크립트, 격리 포트 백엔드)는 정리, PM의 기존 로컬 dev 서버(3000/8000)는 그대로 살아있고 이제 정상 동작.

## 한계 / 확인 필요 항목

- **미확정 항목**: `tier` 값으로 1(1성)이 관측된 적은 없으나(현재 10개 조합 데이터는 "이상적인 최종 보드" 추천이라 2·3만 나옴), 필드 자체는 정수라 향후 1이 나오면 별 1개가 자동으로 표시된다(색상은 `starLevel >= 3` 기준 분기라 1성도 골드로 표시됨 — 별도 색상 지정 없음, 필요시 PM 확인).
- **transform-gpu 회귀 테스트는 없음**: jsdom은 실제 픽셀 페인트를 하지 않아 이 클래스가 없어도 단위 테스트는 통과한다 — 이번에 발견한 버그는 브라우저 실렌더링으로만 잡을 수 있었다(코드 주석으로 원인·근거를 남겨둠).
