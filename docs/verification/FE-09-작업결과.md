## 설계

- **세션**: api-spec.md대로 `crypto.randomUUID()`를 클라이언트에서 발급해 컴포넌트 상태로만 유지한다(로그인/회원 개념 아님, policies.md 4번). 위젯이 `layout.tsx`의 `{children}` 바깥에 있어 페이지 전환(클라이언트 내비게이션) 중에는 대화가 유지되고, 새로고침 시에는 리셋된다 — 화면설계서 2.7 "세션 유지 시각적 표시 없음" 가정과 함께 별도 영속화(localStorage 등) 요구사항이 명시돼 있지 않아 추가하지 않았다.
- **SSE 파싱**: `chat_stream.py`(`build_sse_stream`)가 내보내는 `data: <token>\n\n` 반복 + `event: done\ndata: [DONE]\n\n` 포맷을 `chat-stream.ts`가 그대로 파싱한다. 토큰은 원문이 `" ".join()`으로 쪼개진 단어이므로 프론트에서 공백으로 재조립한다.
- **후속질문칩(SuggestedFollowupChips)**: 화면설계서 2.7 컴포넌트 표에 `visible/hidden` 상태만 정의돼 있고, 백엔드(CHAT-01~09) 어디에도 맥락별 후속 질문을 생성하는 필드가 없다. **가정(PM 확인 필요)**: 의도 4분류(glossary.md)를 대표하는 고정 예시 질문 4개를 대화 시작 전(빈 상태)에만 노출하고, 첫 메시지 이후에는 숨긴다. 화면설계서 2.7 자체가 이미 여러 항목을 "PRD 미명시 - 가정"으로 명시하는 문서라 동일한 방식을 따랐다.
- **링크 클릭 계측**: CHAT-07이 만든 `[이름](url)` 링크를 클릭하면 `link_click_events`(schema.md) 적재용 `POST /chat/events/link-click`을 함께 호출한다. 이미 존재하는 KPI 인프라(KPI-01)를 활용한 것으로, 실패해도 실제 페이지 이동은 막지 않는다(`postLinkClickEvent`가 조용히 무시).
- **반응형**: 기존 `Gnb`/`ResponsiveFilter`와 동일하게 Tailwind `md:` 하나로 모바일/데스크톱·태블릿 2단계만 구분(프로젝트 전반의 기존 관례). 패널은 모바일에서 `fixed inset-0`(전체화면 바텀시트), `md:` 이상에서 `md:inset-auto md:bottom-24 md:right-6 md:h-[505px] md:w-[360px]`(design-tokens.md "우하단 플로팅 360×505, radius 10")로 전환된다. FE-01 placeholder는 모바일에서도 작은 플로팅 패널이었던 버그를 이번에 함께 수정했다.
