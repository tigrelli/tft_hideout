# FE-14 작업결과 — 조합 상세 헥스 배치도 실좌표 반영

- **상태**: 완료(PM 승인)
- **일자**: 2026-08-06
- **PM 요청으로 추가된 배경 격자선**: 빈 칸도 옅은 회색 헥스 테두리로 표시(`EmptyHexCell`, 7×4 전체 28칸), 몇 번째 줄·칸에 배치됐는지 한눈에 보이게 함

## 배경

조합 상세(HexBoard)는 그동안 `is_carry` 기반 전열/후열 휴리스틱으로 배치를 시각화했다("실제 매치 데이터가 아님" 캡션 명시). PM이 티어 데이터에 증강체 선택 정보가 있는지 문의하는 과정에서 op.gg `tft_list_meta_decks` 응답을 직접 재조회했고, 그 안의 `units[].cell.{x, y}`(x: 1~7, y: 1~4, 4행×7열)에 실제 랭커 배치 좌표가 있음을 발견했다. 이전 스파이크 요약본(`docs/spike/opgg-schema.md`)에는 `stat` 필드 샘플만 남아 있어 이 필드를 놓쳤던 것으로 확인 — "op.gg·Riot 공식 API 어디에도 보드 좌표가 없다"던 이전 판단은 정정되었다.

## 운영 데이터 백필

마이그레이션을 실제 Supabase 개발 DB에 적용한 뒤, op.gg `tft_list_meta_decks` 1회 재호출로 `comp_champions.cell_x/cell_y`만 UPDATE하는 1회성 스크립트를 실행(레포 미커밋, 다른 테이블 미변경). 현재 10개 조합 중 8개(69명)에 실좌표 반영, 2개 조합은 op.gg 응답에서 해당 `riot_comp_id`를 찾지 못해(메타 변동으로 추정) 기존 휴리스틱 폴백으로 정상 동작 확인. 로컬 백엔드로 `GET /comps/{id}` 8건 실좌표 포함·2건 null 확인.

## 참고

- 좌표 y=1~4의 화면상 위/아래 방향, x 오프셋 방향(짝수 행을 오른쪽으로 밀도록 구현)은 op.gg 응답에 방향 메타데이터가 없어 임의로 정한 값이다 — 실제 게임 화면과 좌우/상하가 반전돼 보일 수 있으나 상대적 배치(누가 누구 옆/앞에 있는지)는 실데이터 그대로다. 필요하면 CSS 값만 뒤집으면 된다.
