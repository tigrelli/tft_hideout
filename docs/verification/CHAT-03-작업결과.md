## 결과 요약

설계서 4.4.1 원문을 그대로 코드에 반영:

- **시스템 프롬프트**: 원문 7규칙(검색문서만 근거, 패치버전 명시, 정확한 명칭만 언급, null win_rate 언급 금지, 근거문서 종류 명시, 범위밖 질문 안내, 프롬프트 인젝션 방어) + 의도별 추가지시 1줄(같은 표: 조합추천/아이템추천/증강체추천/일반전략 4종)
- **few-shot 예시**: 설계서가 "권장"한 1~2개(질문-근거-답변 쌍)를 합성 데이터로 고정 삽입(CLAUDE.md 10.2)
- **조립 순서**(WBS TASK 설명 그대로): 시스템 프롬프트(+의도별 지시) → few-shot → `[검색된 문서]`(기준 패치 명시, 없으면 "검색된 문서 없음") → `[이전 대화]`(있을 때만, Q/A 페어 순서 보존) → CHAT-04의 `wrap_user_message()` 결과를 그대로 이어붙임(`[사용자 메시지]...[/사용자 메시지]`)
- CHAT-02(`hybrid_search` 결과 `list[MetaDocumentEmbedding]`), API-10/CHAT-04(`get_conversation_history` 결과 `list[ChatLog]`)를 그대로 입력 타입으로 받아 별도 변환 계층 없이 조립. 엔드포인트 배선(SSE 흐름에 실제로 연결)은 CHAT-05에서 진행(API-09/CHAT-02와 동일한 "뼈대 우선" 패턴).

## 자체 검증

- pytest 7건 신규(backend 전체 **128/128 통과**), ruff check/format 통과
  - **WBS 핵심 요구사항**: 전체 조합 결과를 고정 문자열과 정확히 비교하는 스냅샷 테스트(시스템프롬프트/few-shot/검색문서/대화이력/질문 순서·구분자 전부 검증)
