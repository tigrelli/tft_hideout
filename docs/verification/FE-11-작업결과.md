## 배경

FE-03(`FilterBar`)·FE-05(`ChampionSelect`)·FE-06(`TierFilterBar`)가 각자 거의 동일한 Dropdown/BottomSheet 마크업을 독립적으로 구현하고 있었다(코드 중복). FE-10(이미지 최적화)은 선행 TASK인 FE-07·FE-08이 SET-16(Riot API 키) 대기로 아직 못 끝나 착수 불가하고, 실제 이미지 자산도 아직 없어(현재 전부 placeholder) PM과 상의 후 FE-11로 순서를 바꿔 먼저 진행했다.

## 설계

- **`FilterDropdown`**(순수 셀렉트): `label`/`value`/`options`/`onChange`/`placeholder`(선택) props. 값 타입을 항상 `string`으로 통일해 화면별 값 타입(문자열 유니온, 숫자 id)은 호출부에서 얇게 변환한다.
- **`ResponsiveFilter`**(Dropdown+BottomSheet 조합): 데스크톱/태블릿용 `FilterDropdown`(`hidden md:block`)과 모바일 트리거 버튼+바텀시트 안의 또 다른 `FilterDropdown` 인스턴스를 같은 `value`/`onChange`로 렌더링 — 두 인스턴스가 항상 같은 상태를 공유한다(WBS 테스트 요구사항).
- **FE-05 `ChampionSelect`는 `ResponsiveFilter`가 아니라 `FilterDropdown`만 재사용**(의도적 설계 결정): 화면설계서 2.3은 이 필터를 브레이크포인트와 무관하게 항상 Dropdown으로 유지하도록 명시하고 있고(바텀시트로 전환되는 건 build-priority-detail 패널뿐), 이미 PM 승인된 FE-05 동작이라 여기에 바텀시트를 새로 추가하지 않았다. "3개 화면에서 재사용"이라는 DoD는 `FilterDropdown` 공용 primitive를 통해 충족(FE-03·FE-05·FE-06 전부 사용), `ResponsiveFilter`(바텀시트 포함 조합)는 실제로 바텀시트가 필요한 FE-03·FE-06 2개 화면이 재사용.
- 리팩터 전후로 최종 렌더링 DOM(클래스명·문구·구조)을 완전히 동일하게 유지 — 기존 `filter-bar.test.tsx`/`tier-filter-bar.test.tsx`/`item-builds-view.test.tsx`를 한 글자도 안 고치고 그대로 통과시켜 무회귀를 확인했다.
