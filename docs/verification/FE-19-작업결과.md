## 원인

  - 캐시를 우회한 요청은 사이트 루트까지 **522**(Cloudflare가 원본에 연결 못 함)로 약 20초 뒤 실패했다.
  - 일반 요청은 200이었지만 `cf-cache-status: STALE`, `age` 약 9시간(`max-age=3600`)이었다. 지역 캐시에 남은 파일만 응답되고, 사용자 쪽 캐시에 없던 아이콘 3개가 실패한 것이다.
  - DB의 아이콘 주소는 정상이었다(18.5와 동일). 프론트는 `images.unoptimized: true`라 브라우저가 CDragon에서 이미지를 직접 받는다.
- **레이아웃 깨짐(우리 결함)**: `next/image` 사용처 5곳 모두 "주소가 null"일 때만 폴백 타일을 썼고, 주소는 있는데 불러오지 못한 경우는 처리하지 않았다. 그래서 24px 상자에 alt 텍스트가 한 글자씩 세로로 쌓였다.

## 구현

`FallbackImage`(클라이언트 컴포넌트)가 `next/image`를 감싼다. 주소가 없거나 로드에 실패하면 `fallback`을 렌더링한다. 각 사용처는 기존 "주소 없음" 폴백 마크업을 그대로 `fallback`으로 넘기므로, 실패 시 모양이 기존 폴백과 같다.

- **실패한 주소 기억**: 실패한 주소를 상태로 들고 있어서, 주소가 바뀌면(다른 챔피언 선택, 패치 갱신) 자동으로 다시 시도한다.
- **하이드레이션 전 실패 감지**: 서버 렌더링된 `<img>`가 React 연결 전에 실패하면 onError가 전달되지 않는다. `next/image`는 이 경우 src를 다시 넣어 재요청한다(설치된 Next 16.3 소스 `image-component.js`에서 확인). 하지만 이번 같은 장애에서는 522 응답까지 약 20초가 걸려 그동안 깨진 이미지가 보인다. 그래서 마운트 시점에 `complete && naturalWidth === 0`이면 즉시 폴백으로 바꾼다.
- **헥스 배치도 예외**: `fill` 이미지라 링 테두리 래퍼 안에 있어야 해서, 실패 시 이름 두 글자를 같은 링 안에 표시한다. 주소가 아예 없는 경우의 기존 폴백(링 없음)과 약간 다르다.
