## 문제와 원인 분류

CHAT-20/22가 출처 신뢰도 라벨링·쿼리 스코핑을 도입했음에도, 저품질/무관 출처를 오독하거나 그대로 이어붙여 확정적으로 틀린 결론을 내리는 문제가 재발. 실제 응답(`results_B/D/E.json`)을 직접 확인해 원인을 4갈래로 분류했다.

| 유형 | 해당 질문 | 실제 증상 |
|---|---|---|
| **① 여러 출처 조합 추론** | D4 | "듀오 파트너 찾기" 서비스(duo.op.gg)와 "랭크 시즌 운영" 공식 기사를 조합해, 어느 쪽도 말하지 않은 "듀오 랭크 큐 가능"이라는 결론을 만들어냄(실제로는 더블업 모드로만 지원) |
| **② 별개 개념 연결** | D10 | "강등 방지 보호 장치"를 물었는데 검색 결과에 있던 "순방"(등수 확정 시 LP 상승 보장, 전혀 다른 개념)을 그 답으로 연결 |
| **③ 오래된 세트/패치 번호를 최신처럼 답함** | B1, E5, E9, E15 | B1은 Facebook 게시물의 "세트 16"을, E5는 URL이 `patch-16-4`인 구버전 패치 링크를, E9·E15는 세트 번호를 혼동해서 답함(E15는 "다음 세트인 세트 15"처럼 현재보다 낮은 번호까지 등장) |
| **④ 인용 형식 결함** | B6(무정보 답변에 불필요한 인용), E4·E15(URL 없는 "[출처]" 라벨만 남음) | 프롬프트 규칙 2번("실제 인용한 출처만 포함")을 LLM이 지키지 않음 |

**이번 TASK에서 코드로 해결하지 않은 것**: B2(질문과 무관한 챔피언 트리비아를 답에 섞음, 그러나 실제 질문에는 정직하게 "확인되지 않았습니다"로 마무리해 핵심 채점기준 자체는 충족할 가능성 높음), B24(한자 혼입 — CHAT-35 별도 스코프), D8·D14(핵심 답 대신 산발적 정보 나열 — Tavily 검색 결과 자체가 빈약한 **검색 품질/리트리벌 문제**라 프롬프트 규칙으로는 근본 해결이 안 됨, 재현 가능한 코드 버그가 아니라 이번 범위에서 제외).

## 구현

1. **`WEB_SEARCH_SYSTEM_PROMPT`에 규칙 3개 추가**(기존 6개 → 9개):
   - 7번: 여러 출처를 조합해 어느 쪽도 명시하지 않은 결론을 만들지 마라(①, D4 대응).
   - 8번: 검색 결과가 질문과 다른 별개 개념을 설명하면 그 내용을 답으로 연결 짓지 마라(②, D10 대응).
   - 9번: `[알려진 사실]` 섹션의 현재 패치와 검색 결과의 세트/패치 번호가 어긋나면 오래된 정보일 수 있음을 밝히고 `[알려진 사실]`을 신뢰하라(③ 대응).
2. **`assemble_web_search_user_turn()`에 `patch_version` 파라미터 추가**(선택 인자, 기본값 `None`으로 기존 호출부·테스트 하위 호환) — `[알려진 사실]` 섹션으로 현재 patch_version을 프롬프트에 주입해 9번 규칙의 대조 기준을 제공. `chat_stream.py`의 `_generate_web_search_answer()`가 이미 알고 있던 `patch_version`을 실제로 전달하도록 배선.
3. **`web_search.py`의 `verify_web_citation()` 확장**: 기존엔 "URL이 아예 없으면" 검증 대상이 없다고 보고 그냥 통과시켰는데, `[출처]`/`[출처 N]` 라벨만 있고 뒤에 `(URL)`이 없는 "빈 인용"(E4·E15)도 할루시네이션 URL과 동일하게 `UNVERIFIED_SOURCE_WARNING`을 붙이도록 수정.
4. **`chat_stream.py`에 `_strip_citation_when_no_info()` 신설**(④, B6 대응): 기존 `_looks_like_no_info_answer()`(CHAT-14가 내부 RAG 경로용으로 만든 함수, 재사용)로 답변 전체가 "확인되지 않았습니다"류 무정보 판정이면, 실제로 근거로 쓰지 않은 인용을 프롬프트 지시(규칙 2번)와 별개로 결정론적으로 제거(CHAT-14와 동일한 "프롬프트 지시 + 결정론적 백스톱" 이중 방어 원칙).

## 한계 및 후속 확인 필요 사항

- D4/D10/B1/E5/E9/E15는 "이런 패턴의 오류를 만들지 마라"는 프롬프트 규칙 추가라 **최종적으로 규칙을 얼마나 잘 따르는지는 2차 Groq LLM의 판단에 달려있다** — 배포 후 프로덕션 재질의로 최종 확인 필요(CHAT-27/28과 동일한 성격의 한계).
- D8/D14는 이번 범위에서 다루지 않았다 — Tavily 검색 결과 자체가 질문이 원하는 구체적 사실(시즌 보상 종류, 랭크 점수-티어 관계)을 포함하지 못해 발생하는 **검색 품질 문제**로, 쿼리를 더 구체화하거나 다른 검색 전략이 필요할 수 있어 별도 TASK 후보로 남겨둔다.
- B2는 "질문과 무관한 트리비아가 섞여 나온다"는 노이즈 문제이지 사실관계 오류는 아니라 이번 범위에서 제외했다 — 재발 빈도가 높아지면 "질문에 명시된 대상과 다른 대상에 대한 정보는 언급하지 마라" 류 규칙 추가를 검토할 것.
