## 착수 중 발견한 버그 (실브라우저 검증으로 발견·수정)

실제 op.gg 데이터(357개 증강체)로 모바일 화면을 검증하다가 **하단 시트(바텀시트)가 뷰포트 하단이 아니라 페이지 맨 아래(스크롤 없이는 안 보이는 위치)에 렌더링되는 버그**를 발견했다. 원인 추적: 일부 증강체 `description`에 공백 없는 매우 긴 원본 op.gg 문자열(예: `@TFTUnitProperty.item:TFT17_Augment_AurelionSolGodAugment@`, 미해석 템플릿 플레이스홀더)이 그대로 들어있는데, 이 텍스트가 줄바꿈 없이 카드 너비를 넘기면서 **모바일 레이아웃 뷰포트 자체가 옆으로 팽창**(`window.innerWidth`가 실제 기기 폭 412px 대신 983px로 관측됨) — 그 결과 `position: fixed; inset: 0`인 바텀시트가 팽창된 전체 문서 크기를 기준으로 배치돼 화면 밖으로 밀려남. `AugmentCard`의 설명 문단에 `wrap-break-word`(Tailwind, `overflow-wrap: break-word`)를 추가해 긴 토큰이 강제 줄바꿈되도록 수정, 재검증으로 `window.innerWidth`가 정상(412px)로 돌아오고 바텀시트가 뷰포트 하단에 정상 표시됨을 확인.

이 버그는 컨텐츠가 여러 화면 높이를 넘는 긴 페이지(증강체 357개)에서만 드러나는 유형이라 FE-03/FE-05의 상대적으로 짧은 리스트에서는 우연히 드러나지 않았을 가능성이 있음(별도 회귀 확인은 안 함, TEST-09 반응형 크로스브라우저 테스트에서 포괄적으로 재확인 권장).

## 알려진 데이터 품질 이슈 (이번 TASK 범위 밖, 참고용 기록)

증강체 `description`에 원본 op.gg 텍스트의 `<br>` 태그가 문자 그대로 노출되고, 일부는 `@TFTUnitProperty...@` 형태의 미해석 수치 템플릿이 그대로 남아있음(위 버그의 원인이기도 함). 실제 수치로 치환하려면 op.gg가 별도 수치 데이터를 안 주는 것으로 보여(DATA-08/DATA-05 스파이크 범위 밖) 배치 단계에서 추가 처리가 필요 — 지금은 카드가 깨지지 않게 줄바꿈만 보정했을 뿐 문구 자체는 원문 그대로다. **PM 결정(2026-08-05)으로 별도 TASK 분리 — `DATA-16`(증강체 설명 템플릿 플레이스홀더 정리, 권장) 신설, `진행현황.md`/`TFT_Hideout_WBS.xlsx` 반영.**
