# CHAT-28 : 작업결과

- **TASK**: 키워드 기반 의도 과잉분류 재발 방지(분류 로직 재설계 검토)
- **상태**: 완료(PM 확인 2026-08-19, 구현·자체검증·도커 재검증 모두 완료)
- **선행 TASK**: CHAT-01, CHAT-21 (TEST-11 A13/B5·11/C3·11/G9/H16에서 발견, 2026-08-19 신설)
- **근거 문서**: `docs/verification/TEST-11-작업결과.md`(카테고리 A/B/C/G/H 결과 상세), `docs/verification/CHAT-27-작업결과.md`(general_rules 신설, 이번 TASK의 라우팅 대상)
- **변경 파일**: `backend/services/intent_classification.py`, `backend/services/chat_preprocessing.py`, `backend/tests/test_chat28_intent_disambiguation.py`

## 문제

카테고리 키워드가 포함되면 실제 질문 의도(메커니즘 설명)와 무관하게 그 카테고리의 "추천 요청"으로 오분류되는 패턴이 A~H 전 카테고리에 걸쳐 반복 재발: A13(증강 메커니즘 질문→augment_recommendation 오분류), B5·B11(무관한 조합 통계 혼입), C3·C11(무관한 증강체/일반론 혼입), G9(리전 질문이 웹검색으로 오검색), H16(패치 예측 질문이 패치버전 조기반환에 잘못 가로채임).

## 대상 7개 질문별 실제 원인과 조치

먼저 7개 질문을 실측한 결과, 원인이 **세 갈래**로 갈렸다 — 전부 같은 코드를 고치는 문제가 아니었다.

| 질문 | 실측 원인 | 조치 |
|---|---|---|
| **A13** | "오그먼트" 단일 키워드로 1차 확정 | ✅ 코드 수정(메커니즘 질문 신호) |
| **B11** | "조합" 단일 키워드로 1차 확정 | ✅ 코드 수정(메커니즘 질문 신호) |
| **H16** | "어떤"이 "패치"가 아니라 "챔피언"을 수식하는데도 신호 단어로 오매칭 | ✅ 코드 수정(배제 단어 확장 + 순서 변경) |
| **G9** | 원래는 웹검색 오검색이었으나, **CHAT-26(2026-08-19 완료)이 chatbot_meta로 이미 가로채 해결**됨 | 회귀 테스트만 추가(수정 불필요) |
| **B5** | "시너지"는 애초에 1차 키워드 매칭 대상이 아니라 원래도 2차 LLM 도달 — 문제는 2차 LLM에 general_rules 선택지가 없었던 것 | CHAT-27이 이미 해결(범주 추가), 여기선 회귀 확인만 |
| **C3** | "아이템"+"조합" 이중 매칭이라 원래도 애매함으로 2차 LLM 도달 — B5와 동일한 이유 | CHAT-27이 이미 해결(범주 추가), 여기선 회귀 확인만 |
| **C11** | "아이템"+"조합" 이중 매칭이라 원래도 2차 LLM 도달(C3와 동일) | CHAT-27이 이미 해결 + 이번 신호도 중복 방어로 매칭 |

## 구현

1. **`intent_classification.py`**: `_MECHANISM_QUESTION_SIGNAL` 신설 — "언제, 몇 개/명"(A13류 절차 질문), "~하면 어떤 ~가 나오나요"(B11류 조건부 결과 질문), "단계별"(B5류), "어울리지 않는/안 어울리는"(C11류) 표현이 있으면 `classify_by_keyword()`가 단일 키워드 매칭이어도 확정하지 않고 `None`(2차 LLM 위임)을 반환하도록 수정. **TEST-11 157문항 전체를 이 신호로 스캔한 결과 A13/B5/B11/C11 4문항 외에는 아무 문항도 매칭되지 않아**(정상 추천 요청 오탐 없음) 오탐 위험이 낮다고 판단.
2. **`chat_preprocessing.py`**: `is_patch_version_query()`의 배제 단어 목록(`_PATCH_NOTE_EXCLUSION_WORDS`)에 "상향"/"하향" 추가, 그리고 **배제 단어 확인을 신호 단어 확인보다 먼저** 하도록 순서를 바꿈(기존엔 신호 단어가 매칭되면 배제 단어를 아예 확인하지 않고 곧장 `True`를 반환해 이 조합을 놓쳤음).

## 자체 검증

- **pytest 신규 13건**(`test_chat28_intent_disambiguation.py`): A13/B5/B11/C11이 1차에서 확정되지 않는지, 2차 LLM 매핑이 general_rules로 가는지, 정상 추천 요청(증강체/조합)은 여전히 1차에서 확정되는지(회귀 방지), H16류 미래예측 질문이 더 이상 패치버전으로 오분류되지 않는지, 기존 순수 버전 질의는 여전히 True인지(회귀 방지), G9가 CHAT-26 경로로 이미 해결돼 있는지(회귀 확인).
- **backend 전체 411/411 통과**(기존 398+신규 13건), ruff check/format 클린.
- **batch 전체 139/139 통과**(회귀 없음).
- Docker(test-db) 재검증 완료.

## 한계 및 후속 확인 필요 사항

- A13/B11/H16은 "잘못된 카테고리로의 확정을 막는다"까지가 코드로 보장되는 부분이고, 실제 최종 답변 내용이 정답지 채점기준을 충족하는지는 2차 Groq LLM의 판단(general_rules 분류 정확도 + `GENERAL_RULES_SYSTEM_PROMPT` 답변 품질)에 달려있어 배포 후 프로덕션 재질의로 최종 확인 필요(CHAT-27과 동일한 성격의 한계).
- B5/C3/C11은 이번 TASK에서 코드를 건드리지 않았다(원래도 2차 LLM 도달 대상이었고, CHAT-27이 이미 general_rules 선택지를 추가해뒀음) — 배포 후 세 문항 모두 재질의해 실제로 general_rules로 분류되는지 교차 확인 필요.
- `_MECHANISM_QUESTION_SIGNAL`은 TEST-11 157문항 기준으로 정밀하게 검증됐지만, 실사용 중 새로운 표현(예: 다른 어순의 "언제/몇 개" 질문)은 여전히 놓칠 수 있다 — 재발 시 신호 목록에 계속 추가하는 CHAT-19/21/25와 동일한 점진적 보강 방식.
