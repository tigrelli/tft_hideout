## 착수 전/중 PM과 함께 정리한 설계 결정 3가지

### 1. 조합 상세 URL: 경로 방식 대신 쿼리스트링(`/comps?id=`)
IA v1.2 원문은 `/comps/{comp_id}`(경로 파라미터)지만, 정적 export는 `generateStaticParams()`로 **빌드 시점에 존재하는 comp_id만** 정적 페이지를 만들 수 있다. `comps` 테이블은 패치마다 새 행이 통째로 쌓이는 구조(DATA-10)라 **사실상 매 패치마다 그 패치의 모든 조합상세 링크가 재배포 전까지 깨지는** 문제가 있음을 PM과 논의 중 발견. 대안(Cloudflare 배포 훅으로 패치 감지 시 자동 재빌드)도 검토했으나, 이는 FE-03에서 이미 거부한 "빌드 시점 데이터 고정"(ISR) 문제를 다른 형태로 재도입하는 것이라 판단해 **쿼리스트링 방식으로 전환**(PM 승인 2026-08-04). `docs/reference/glossary.md` URL 표 갱신, FE-03 `CompCard`와 CHAT-07 `chat_links.py`의 링크도 함께 수정.

### 2. API-03 버그: 실제 데이터로 500 에러
`ChampionInComp.recommended_items`가 `dict`로 잘못 선언돼 있었는데 실제 배치(DATA-10)가 만드는 값은 `list`라 **프로덕션에서 이 엔드포인트가 항상 500**이었음(API-03 자체 테스트가 실제 배치 형식과 다른 합성 fixture를 써서 못 잡힘). `dict`→`list[str]`로 수정, 실제 DB로 재현·해결 확인.

### 3. 챔피언/아이템/증강체 이름 조회 공백 해결
API-03이 `champion_id`(정수)·`recommended_items`(원본 아이템 ID)만 줘서 화면에 이름을 못 보여주는 공백을 발견. Riot 공식 API는 정적 데이터를 REST로 안 주고 Data Dragon 전용임을 WebSearch로 확인하는 과정에서, DATA-06이 "연결 실패"로 결론냈던 공식 TFT Data Dragon이 실제로는 연결되고 우리 DB(Community Dragon 기반)와 동일 ID 체계임을 재확인(`docs/spike/tft-ddragon.md` 정정, 데이터 소스는 안 바꿈). 실 데이터로 JOIN 정합성 사전 검증(챔피언 86/86, 아이템 29/29 매칭) 후 API-03 응답에 `name_kr`/`name_en`(챔피언·증강체)과 `recommended_item_names`(아이템)를 JOIN으로 추가.
