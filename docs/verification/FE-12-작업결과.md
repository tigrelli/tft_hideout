## 구현 요약

`/kpi` 페이지에 비밀번호 게이트(미인증 시)와 5개 지표 카드(데이터 최신성/답변 근거율/전환율/사후분석 이용률/응답 지연)를 구현했다. 인증 흐름은 `POST /api/v1/kpi/auth`로 토큰을 발급받아 `GET /api/v1/kpi/summary`에 `Authorization: Bearer` 헤더로 실어 호출하는 방식(KPI-01)을 그대로 따른다. 토큰은 컴포넌트 상태로만 들고 있고 별도로 영속화하지 않는다(새로고침하면 다시 게이트를 통과해야 함) — sessionStorage에 저장해 새로고침을 넘기는 방식을 처음에 시도했으나, `react-hooks/set-state-in-effect` 린트 규칙(effect 본문에서 동기적으로 setState 호출 금지)에 걸려 DoD에 없는 기능이라 단순화 방향으로 제거했다. policies.md 13번에 따라 GNB(`nav-items.ts`)에는 링크를 추가하지 않았고, `layout.tsx`에 `robots: { index: false, follow: false }`를 추가해 검색엔진 색인도 막았다(DoD에는 없으나 "URL을 아는 사람만 접근" 전제를 지키기 위한 최소 추가).

## 실사용 검증(배포 백엔드 + 로컬 백엔드, Playwright로 실제 브라우저 구동)

1. **1차 검증에서 실배포 버그 발견**: 로컬 dev 서버를 배포 백엔드(Render)를 바라보게 띄우고 Playwright로 오답 비밀번호를 제출하자 예상한 401이 아니라 **500 Internal Server Error**가 발생. 원인 조사 결과 `services/kpi_auth.py`의 `verify_password()`가 `os.environ["KPI_DASHBOARD_PASSWORD"]`를 직접 읽는데, KPI-01 완료 당시 이 값이 로컬 `.env`에만 등록되고 **Render 실제 배포 환경변수에는 등록되지 않았던 것**이 원인(KPI-01은 승인 당시 프론트엔드가 없어 이 엔드포인트를 실제 브라우저에서 호출해본 적이 없었음). PM에게 보고 후 PM이 Render 대시보드에서 `KPI_DASHBOARD_PASSWORD`를 직접 등록.
2. **재검증**: 동일한 방식으로 배포 백엔드 대상 재확인 — 오답 시 401 + "비밀번호가 올바르지 않습니다." 게이트 재노출, 정답 시 토큰 발급 → `GET /kpi/summary` 실데이터로 5개 카드 정상 렌더링(스크린샷으로 PM에 제시, 데이터 최신성 평균 2.7분/표본 2건, 근거율·이용률은 RAGAS(KPI-02)·PGA 미구현이라 "데이터 없음"으로 null-safe 표시, 전환율 0.0%(노출 35건·클릭 0건), 응답지연 웜 p50 578ms·전체 p95 1,212ms·콜드스타트 비율 0.6%) 확인.
3. **로컬 백엔드 검증**: PM이 로컬 환경에서도 재확인을 요청, `backend/.venv`의 uvicorn을 8000번 포트로 기동(로컬 Supabase DB 연결, `backend/main.py`의 `ALLOWED_ORIGINS`가 `localhost:3000`만 허용해 프론트도 3000번으로 고정)해 동일하게 오답 401 확인, PM이 직접 정답 로그인·지표 렌더링까지 확인.
