## 배경

CHAT-14 PM 검증 중 "보석 건틀릿을 장착하면 어떤 챔피언의 치명타 확률이 가장 많이 증가할까?"라는 실제 질문에 챗봇이 "정확한 수치는 확인되지 않았다"로만 답한 것을 PM이 검토 요청. 확인 결과 `items.stats`에는 실제 수치(`보석 건틀릿` `CritChance: 35`)가 있었지만, CHAT-14가 만든 `item_chunk_text()`는 `description`(정성적 설명)만 임베딩하고 `stats`(수치)는 전혀 포함하지 않아 RAG 근거 원칙(문서에 없는 내용 추측 금지)상 정상적으로 "확인 안 됨"으로 답한 것이었다(버그 아님, 데이터 공백).

## 설계

- **화이트리스트 방식 채택**: `items.stats`는 op.gg/Community Dragon 원본 툴팁 변수를 그대로 담고 있어 아이템 전체에 걸쳐 distinct 키가 500개 이상이고, 일부는 `{cd951938}` 같은 미해석 해시 키다. 전체를 그대로 노출하면 단위를 알 수 없는 수치가 RAG 문서에 섞여 오답 위험이 커서, 게임적으로 의미가 명확한 핵심 스탯(주문력/방어력/마법 저항력/체력/마나 재생/공격력/치명타 확률/치명타 피해/생명력 흡수/피해량 증폭)만 DATA-07(Legend 목록)·DATA-19(키워드 글로서리)와 같은 성격의 수동 유지 화이트리스트로 관리한다.
- **단위 불일치 실측·대응**: 화이트리스트 후보 키의 실제 값 분포를 전수 조회해 단위를 검증하던 중, `AttackSpeed`·`Omnivamp`는 **같은 키인데도 아이템마다 단위가 다르게 저장돼 있음**을 발견했다(예: `AttackSpeed`가 어떤 아이템은 `0.3`(=30%), 어떤 아이템은 `60`(그 자체로 60%)). 하나의 규칙으로 변환할 수 없어 이 두 키는 화이트리스트에서 제외했다(잘못된 수치를 노출하는 것보다 노출하지 않는 쪽을 택함). 반대로 `AD`는 전 아이템에 걸쳐 항상 0~1 소수(퍼센트 환산 필요)로 일관됐고, `AP`/`Armor`/`MagicResist`/`Health`/`ManaRegen`은 항상 정수 평면 수치로, `CritChance`/`LifeSteal`은 항상 정수 퍼센트 포인트로 일관돼 있어 그대로 채택했다.
- **부동소수점 오차 처리**: op.gg 원본이 float32 유래 값을 담고 있어 `0.35`가 `0.3499999940395355`로 저장된 경우가 있다. `percent_fraction` 단위는 `round(value * 100, 1)`로 반올림해 "+34.99999940395355%" 같은 깨진 문자열이 나오지 않게 했다(1차로 `AttackSpeed`에서 이 문제를 실제로 겪고 발견해 반올림을 추가, 위 단위 불일치 이슈와 별개로 발견한 버그).
- **`item_chunk_text()` 반영**: 화이트리스트에 해당하는 값이 있으면 `"{이름}: {설명} (스탯: {포맷된 스탯})"` 형태로, 없으면(스탯 자체가 없거나 화이트리스트 키가 전부 빠진 아이템) 기존 문장을 그대로 유지한다.

## 한계 및 후속 논의 필요 사항

- **"어떤 챔피언이 가장 많이 증가하나" 질문의 본질적 한계**: 아이템 스탯 보너스는 원래 챔피언마다 다르지 않고 착용자 누구에게나 동일하게 붙는 고정값이라, "어떤 챔피언이 가장 많이 증가하나"라는 질문 자체가 TFT 아이템 메커니즘상 챔피언 간 차이가 없다는 게 정답이다. 이번 수정으로 정확한 수치는 답할 수 있게 됐지만, "그래서 챔피언 간 차이가 없다"는 논리적 결론까지 모델이 스스로 도출하는지는 프롬프트/모델 특성에 달려 있어 결정론적으로 보장할 수 없다(실제 확인한 답변도 수치는 정확했지만 "가장 많이 증가합니다"처럼 여전히 챔피언 비교 프레이밍을 유지했다). 이 부분을 더 다듬을지는 PM 판단 필요 — 별도 TASK로 다룰 만큼 우선순위가 높은지 확인 요청.
- **제외된 키(`AttackSpeed`, `Omnivamp`)**: 위 설계에서 설명한 단위 불일치로 화이트리스트에서 제외했다. 필요하면 아이템별로 직접 확인해 개별 보정 테이블을 만드는 후속 작업이 가능하나, 이번 범위에서는 잘못된 수치를 노출하지 않는 쪽을 우선했다.
- **문구·수치는 원본 그대로**: DATA-19와 같은 성격 — `stats`의 값 자체는 op.gg/Community Dragon 원본을 그대로 쓰고 있어(가공 없음) 별도 검수는 필요 없으나, 화이트리스트에 포함할 스탯 선정(예: `HexRadius`, `Duration` 등을 계속 제외할지)은 PM 판단이 필요하면 언제든 추가 가능.
