> 근거: 개발설계서 v1.7 4.4.2·4.4.3·4.5.1·4.5.2, 요구사항정의서 v1.1 NFR-SEC(01~05)·FR-PGA(01~11), `/docs/reference/policies.md`

## 설계 중 확정이 필요했던 사항 (원본 문서에 없어 이번에 결정)

이 항목들은 개발설계서에 계산식은 있지만 경계 조건까지는 명시돼 있지 않아, 이 문서 작성 과정에서 아래처럼 확정한다. PM 승인 시 이 결정도 함께 승인되는 것으로 간주한다.

1. **PGA-04 가중치 기준**: "캐리는 가중치 2, 나머지는 1"의 가중치는 **비교 대상 메타 조합(comp)의 `comp_champions.is_carry` 값 기준**으로만 정해진다. 플레이어 보드에만 있고 해당 조합에는 없는 챔피언은 가중치 1(그 조합엔 carry 정보가 없으므로).
2. **PGA-04 매칭 대상**: 이탈도는 **현재 패치의 모든 메타 조합과 비교해 가장 유사도가 높은(이탈도가 가장 낮은) 조합 하나**를 선택(`matched_comp_id`)한다. 동률이면 `comps.play_rate`가 더 높은 쪽을 선택한다(더 흔한 해석 우선).
3. **PGA-05 분모 정의**: "보유 총 완성 아이템 수"는 **매칭된 조합 캐리 여부와 무관하게 플레이어 보드 전체 챔피언이 보유한 완성 아이템 총합**이다.
4. **PGA-06 0으로 나누기**: 증강체를 하나도 선택하지 않은 입력은 게임 로직상 불가능하지만(TFT는 항상 3개 선택), 방어적으로 `augment_synergy=None`을 반환하고 예외를 던지지 않는다.
5. **PGA-07은 LLM 생성**이라 출력 문자열을 고정값으로 검증할 수 없다. 대신 (a) 프롬프트에 계산된 점수·등수가 정확히 주입되는지, (b) 후처리에서 원 수치 패턴이 노출되면 걸러지는지를 검증한다(CHAT-06과 동일한 "생성 후 정규식 재검사" 원칙).

## API-05 — GET /catalog/augments (Legend 승률 비노출)

정책: `docs/reference/policies.md` 1번. `is_legend_related=true`인 증강체는 API 응답 JSON에 `win_rate` 숫자 자체가 없어야 한다(프론트 CSS로 숨기는 방식 금지 — 방어 원칙: 클라이언트를 신뢰하지 않는다).

| # | 입력 | 기대 출력 | 비고 |
|---|---|---|---|
| 1 | `is_legend_related=false`, `win_rate=0.42` 증강체 | 응답에 `win_rate: 0.42` 그대로 포함 | 정상 케이스 |
| 2 | `is_legend_related=true`, `win_rate=0.55` 증강체 | 응답에서 `win_rate` 필드가 `null`(키 자체를 생략하지 않고 `null`로 명시 — 프론트가 "승률 표시 안함" 분기를 타도록) | 핵심 정책 케이스 |
| 3 | `is_legend_related=true`인 증강체와 `false`인 증강체가 같은 목록 응답에 혼재 | `true` 항목만 `win_rate: null`, 나머지는 정상 노출 | 목록 API 혼합 케이스 |
| 4 | 응답 JSON 전체를 문자열화해 정규식 `\d+(\.\d+)?%?`로 스캔 | `is_legend_related=true` 항목 근처에 숫자 패턴이 전혀 없어야 함 | "DOM에 숫자 자체가 없어야 함" 요구사항의 자동 검증판 |

## PGA-04 — 조합 이탈도 계산 (comp_deviation)

식: `이탈도 = 1 − 가중 자카드 유사도`, 유사도 `= Σ(교집합 챔피언 가중치) / Σ(합집합 챔피언 가중치)`, 캐리(`is_carry=true`) 가중치 2·나머지 1. 구간: `[0, 0.3)` 메타 그대로 / `[0.3, 0.6)` 변형 / `[0.6, 1]` 이탈.

| # | 메타 조합(comp) | 플레이어 보드 | 계산 | 기대 이탈도 | 기대 구간 |
|---|---|---|---|---|---|
| 1 | 캐리(w2): 이즈리얼, 진 / 서포터(w1): 룰루, 자야, 카르마 | 이즈리얼, 진, 룰루, 자야, 카르마 (완전 일치) | 교집합=2+2+1+1+1=7, 합집합=7 | 0.0 | 메타 그대로 (경계값: 0 포함) |
| 2 | 캐리(w2): 이즈리얼, 진 / 서포터(w1): 룰루, 자야, 카르마 | 이즈리얼, 진, 룰루, 가렌, 사미라 | 교집합=2+2+1=5, 합집합=2+2+1+1+1+1+1=9 | 1-5/9 ≈ 0.4444 | 변형 |
| 3 | 캐리(w2): 이즈리얼, 진 / 서포터(w1): 룰루, 자야, 카르마 | 가렌, 사미라, 신지드, 워윅, 문도 박사 (완전 불일치) | 교집합=0, 합집합=2+2+1+1+1+1+1+1+1+1=12 | 1.0 | 이탈 |
| 4 | 위와 동일 | 이즈리얼(carry 일치), 그 외 4명 모두 불일치 | 교집합=2, 합집합=2+2+1+1+1+1+1+1+1=11 | 1-2/11 ≈ 0.8182 | 이탈 |
| 5 | 후보 comp A(유사도 0.55), comp B(유사도 0.58) 두 조합과 동시 비교 | 동일 플레이어 보드 | argmax 유사도 = comp B | `matched_comp_id` = comp B | 여러 메타 조합 중 최댓값 선택 로직 확인 |
| 6 | 이탈도 정확히 0.3, 정확히 0.6이 되도록 구성한 합성 케이스 | - | - | 0.3→"변형"(하한 포함), 0.6→"이탈"(하한 포함) | 구간 경계값(`[a,b)` 규칙) 명시 확인 |

## PGA-05 — 아이템 집중도 계산 (item_concentration)

식: `집중도 = 매칭조합 캐리 챔피언들이 보유한 완성 아이템 수 / 플레이어 보드 전체 완성 아이템 수`. 보조 지표: 캐리 챔피언별 실보유 아이템과 `champion_item_builds.item_combination` 추천 세트의 멀티셋 교집합 개수.

| # | 상황 | 계산 | 기대 결과 |
|---|---|---|---|
| 1 | 매칭 조합 캐리=이즈리얼(완성템 3개), 진(완성템 2개). 그 외 챔피언 합쳐 완성템 4개(보드 전체 9개) | 5/9 | 집중도 ≈ 0.5556 |
| 2 | 캐리에게 완성템이 0개, 서포터들이 전부 보유(보드 전체 6개) | 0/6 | 집중도 0.0(경계값) |
| 3 | 보드 전체 완성 아이템이 0개(초반 조기 종료 등 극단 케이스) | 0/0 | `item_concentration=None` 반환(0으로 나누기 방지), 예외 아님 |
| 4 | 이즈리얼 추천 빌드 `[무한의 대검, 붉은 덩굴정령의 아이, 수호천사]`, 실보유 `[무한의 대검, 붉은 덩굴정령의 아이, 마법공학 총검]` | 멀티셋 교집합 | 일치 개수 2 |
| 5 | 실보유에 동일 아이템 2개 중복(`[무한의 대검, 무한의 대검, 수호천사]`), 추천 빌드에도 무한의 대검 2개 포함 | 멀티셋(중복 개별 카운트) | 무한의 대검 일치 2개로 카운트(단순 집합 교집합이었다면 1개로 잘못 계산됨 — 이 차이를 검증) |

## PGA-06 — 증강체 시너지 계산 (augment_synergy)

식: `시너지 = 매칭조합 comp_augments에 포함된 선택 증강체 수 / 선택한 전체 증강체 수`

| # | 매칭조합 comp_augments | 플레이어 선택 증강체(3개, TFT 규칙상 항상 3개) | 기대 결과 |
|---|---|---|---|
| 1 | 스타 관통자, 마나 흐름 목걸이, 이차 저지 | 스타 관통자, 조합원 결속, 무기의 달인 | 1/3 ≈ 0.3333 |
| 2 | 스타 관통자, 마나 흐름 목걸이, 이차 저지 | 스타 관통자, 마나 흐름 목걸이, 이차 저지(전부 일치) | 3/3 = 1.0(경계값 상한) |
| 3 | 스타 관통자, 마나 흐름 목걸이, 이차 저지 | 조합원 결속, 무기의 달인, 황금 갑옷(전부 불일치) | 0/3 = 0.0(경계값 하한) |
| 4 | (설계상 발생 불가하지만 방어적으로) 선택 증강체 0개 입력 | - | `augment_synergy=None`, 예외 아님 |

| # | 검증 대상 | 방법 | 기대 결과 |

| 4 | 다음 게임 제안 근거 | `matched_comp_id` 기준 추천 아이템·증강체 목록을 mock으로 주입 | 코칭 프롬프트에 해당 추천 목록이 포함되고, 라운드 재현성 표현("그때 리롤했어야") 금지 지시가 시스템 프롬프트에 포함되는지 확인 |
